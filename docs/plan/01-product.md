# 01. 제품 요구사항과 사용자 경험

## 1. 문제와 목표

현재 SSH는 명령·로그를, Jump Desktop는 원격 화면을, 별도 MCP는 UI 입력을 맡는다. 사용자가 각 도구의 연결·세션·오류 복구를 따로 관리해야 해서 AI에게 “Windows 앱을 검증해줘”라고 맡긴 뒤 완료까지 이어지지 않는다.

제품은 컴퓨터 선택부터 연결, 파일 반입, 앱 실행, 관찰, 디버깅, 조치, 재검증, 결과 반출까지 이어지는 작업 공간이다. AI는 환경을 조회하며 다음 행동을 선택할 수 있어야 하고, 사람도 동일 기능을 직접 사용할 수 있어야 한다.

## 2. 사용자 확정 요구 / 설계 가정

| 구분 | 내용 |
|---|---|
| 사용자 요구 | Windows 호환성·UI 검증을 AI에게 맡긴다 |
| 사용자 요구 | RDP/VNC 등의 연결과 AI Native 디버깅·운용·점검·QA를 통합한 앱·CLI를 만든다 |
| 사용자 선호 | 기존 Jump Desktop에 기능을 결합하는 형태를 우선한다 |
| 사용자 요구 | 사람도 직접 사용 가능해야 한다 |
| 사용자 요구 | 파일 이동과 전송도 자유롭게 수행한다 |
| 사용자 위임 | 구현은 다른 에이전트가 담당하며 이 문서는 기획·스펙 인계다 |
| 초기 범위 가정 | macOS 제어 앱/CLI/MCP → Windows 11 x64 실기기 우선. 다른 OS/ARM64는 확장 단계 |
| 설계 제안 | 공식 Jump 기능 재사용 + 부족한 명령·파일·진단·작업 관리 기능만 보완 |

초기 범위는 전 플랫폼 지원 완료를 뜻하지 않는다. RDP·VNC·Fluid는 연결 선택지로 다루고 각 조합의 실제 가능 기능을 노출한다. 특정 프로토콜 이름만 지원 목록에 올리고 UIA·파일·명령까지 된다고 표시하지 않는다.

## 3. 핵심 시나리오

### S1. AI에게 Windows 앱 QA 위임

사용자가 빌드 파일 또는 빌드 경로와 테스트 목표를 지정한다. AI가 대상 환경을 점검하고 파일을 전송해 앱을 실행한다. UI와 앱 로그·네트워크 오류를 함께 확인한다. 실패하면 해당 단계의 화면·로그·버전·재현 절차를 모으고, 수정 빌드를 다시 전송해 같은 시나리오를 재검증한다. 사용자는 중간에 Jump로 같은 세션을 볼 수 있다.

### S2. 사람이 디버깅하다 AI에 인계

사람이 앱에서 문제를 재현한 뒤 “현재 창에서 이 오류를 조사”를 선택한다. 앱이 대상 창·프로세스·디버깅 연결·최근 로그·선택한 파일을 작업 컨텍스트로 묶는다. AI는 현 상태부터 이어서 조사한다. 사람에게 제어권을 돌려주어도 이미 수집한 결과와 진행 상태는 유지한다.

### S3. 연결이 끊기는 장시간 작업

빌드·전송·테스트 중 클라이언트 연결이 끊긴다. 원격 작업은 사전 정책에 따라 계속되거나 중단된다. 재접속 시 작업 ID로 상태를 조회하고 기존 실행에 다시 붙는다. 테스트가 두 번 실행되거나 파일이 중복 배포되면 실패다.

### S4. 파일을 앱으로 끌어다 놓기

사람이 설치 파일/폴더를 대상 컴퓨터의 파일 패널로 드롭한다. 전송 큐에서 진행률과 충돌 해결을 보고 원격 경로를 바로 복사하거나 실행한다. AI도 같은 전송 API를 이용해 결과 파일·로그·덤프를 로컬로 가져온다.

### S5. 운영 점검과 조치

CPU·메모리·디스크·앱 버전·프로세스·서비스·최근 오류를 조회한다. 대상 앱 재시작 등 허용된 조치를 실행하고 상태가 회복됐는지 확인한다. 조치 전후 결과와 영향 범위를 남긴다. 점검만 요청하면 변경을 수행하지 않는다.

## 4. 기능 요구사항

P0는 실사용 첫 버전 필수, P1은 확장 단계다. 세부 수치는 초기 제안이며 실측 근거 없이 완료 기준을 낮추지 않는다.

| ID | 우선순위 | 요구사항 | 사용자에게 보여야 할 결과 |
|---|---|---|---|
| CON-01 | P0 | 컴퓨터 등록·연결·연결 해제·상태 점검 | 대상 ID, OS/아키텍처, 사용자 세션, 기능별 준비 상태 |
| CON-02 | P0 | Jump 연결 열기와 동일 원격 세션 매핑 | 사람이 보는 화면과 AI가 조작하는 세션이 일치 |
| CON-03 | P0 | 자동 재연결·작업 재부착 | 연결 복구와 작업 결과 확인을 구분 |
| UI-01 | P0 | 화면/창/디스플레이 캡처·UI 요소 조회 | 캡처 시각, 화면 크기/DPI, 대상 창, 최신성 |
| UI-02 | P0 | 클릭·키·한글/영문 입력·스크롤·드래그·창 관리 | 실행 여부 및 실행 후 관찰 결과 |
| UI-03 | P0 | 사람/AI 제어권 인계·즉시 중지 | 현재 제어자, 대기 이유, 반환/취소 |
| RUN-01 | P0 | 명령·대화형 터미널·프로세스 실행 | stdout/stderr, 종료 코드, 작업 ID, 취소/재부착 |
| OPS-01 | P0 | 환경·프로세스·리소스·서비스·로그 점검 | 구조화된 진단 및 근거 파일 |
| DBG-01 | P0 | Electron 렌더러/메인 디버깅 연결 관리 | 대상 프로세스/포트, 연결 상태, 로그/오류 |
| DBG-02 | P0 | 지원 디버거 하나의 실제 중단점·스택·변수·재개 | 소스/심볼 경로와 실제 디버깅 증거 |
| DBG-03 | P1 | 네이티브 덤프 분석·성능 추적·추가 런타임 어댑터 | 지원 기능별 상태, 분석 산출물 |
| QA-01 | P0 | 자유 탐색과 저장된 시나리오 실행 | 단계별 assertion, 성공/실패/차단/미검증 |
| QA-02 | P0 | 빌드 반입→실행→검증→결과 수집 | 재현 가능한 실행 기록과 결과 묶음 |
| QA-03 | P1 | 버전·해상도·언어·OS 매트릭스, 회귀 비교 | 환경별 결과 및 실패 차이 |
| FILE-01 | P0 | 파일/폴더 업로드·다운로드, 탐색·검색·정보 조회 | 원본/목적 경로, 크기, 전송 진행률 |
| FILE-02 | P0 | 원격 내부 복사·이동·이름 변경·폴더 생성 | 실제 결과 경로, 충돌/권한 오류 |
| FILE-03 | P0 | 로컬↔원격 이동, 중단 재개·무결성 검증 | 목적지 검증 후 원본 제거, 부분 성공 명시 |
| FILE-04 | P0 | 덮어쓰기 정책·미리보기·취소 | replace/skip/rename/fail 선택, 변경 목록 |
| FILE-05 | P1 | 양방향 동기화·변경 감지·호스트 간 전송 | 동기화 계획, 삭제/충돌 처리, 재개 |
| API-01 | P0 | GUI·CLI·MCP 공통 동작 계약 | 어느 경로에서 시작해도 동일 작업을 조회/제어 |
| REL-01 | P0 | 설치·업데이트·복구·제거 | 한 번의 온보딩, 버전 호환 확인, 자기 진단 |

원격 파일 편집은 인코딩을 인식한 미리보기/쓰기와 충돌 감지를 포함한다. 바이너리는 텍스트 편집으로 처리하지 않는다. 파일 삭제는 휴지통 지원 여부를 표시하고 영구 삭제는 별도 명시적 동작으로 분리한다.

## 5. 사람용 앱

- **컴퓨터 목록:** 최근 연결, 준비 상태, 연결/Jump에서 열기, 진단 실행.
- **작업 공간:** 대상/세션을 상단에 고정하고 화면, 터미널, 파일, 프로세스/로그, 디버거, QA 결과를 탭으로 배치한다.
- **화면:** 공식 Jump 화면 또는 Mission Control을 여는 동작을 우선 제공. 임베딩이 검증되지 않으면 외부 창으로 열고 대상 정보를 동기화한다. 단순 외부 링크만 제공하고 작업 상태가 분리되면 통합 완료로 보지 않는다.
- **파일:** 로컬/원격 2패널, 드래그 앤 드롭, 전송 큐, 이어받기, 경로 복사, 해당 파일 실행/로그로 열기.
- **작업 타임라인:** 사람/AI가 수행한 동작, 시각, 대상, 결과와 첨부 증거. 실패/대기 항목에서 복구 또는 인계 가능.
- **제어권:** 관찰 중/AI 조작 중/사람 조작 중/로그인 필요를 명확히 표시. OS 로그인·비밀 입력은 사람이 수행하는 경로 제공.
- **설정:** 연결 프로필과 권한, 파일 작업 루트, 보존 기간, 디버깅 어댑터. 기술 내부 옵션은 고급 설정으로 제한.

앱에 자체 LLM 챗봇을 넣는 것은 P0 필수가 아니다. 외부 Codex/Claude 등에서 MCP로 조작해도 사람용 앱에 같은 상태가 표시되어야 한다.

## 6. 유동적인 AI 사용의 의미

정해진 매크로 실행에 한정하지 않는다. AI는 사용 가능한 기능과 상태를 조회하고, 화면·UIA·디버거·파일·명령을 선택적으로 조합한다. 지원하지 않는 기능에는 이유와 대안을 반환한다. 특정 LLM 공급자에 묶지 않는다. 자연어 성공 추정 대신 구조화된 관찰과 assertion을 남긴다.

## 7. 첫 버전에서 제외하는 것

자체 RDP/VNC/Fluid 프로토콜 재구현, 별도 클라우드 원격 접속망, 모든 OS/모든 디버거 지원, VM 생성·스냅샷 관리, OS 잠금/UAC 우회, AI의 무조건 관리자 실행, 전용 IDE 전체 구현은 첫 버전 목표가 아니다. 원격 호스트와 연결 어댑터의 확장 지점은 유지한다.

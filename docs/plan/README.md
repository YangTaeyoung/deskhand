작성: 2026-10-20 · 상태: 사용자 요구사항 정리 + 기술 제안 v0.1 · 제품명 Deskhand, CLI `deskhand`(Go)

**목적: 사람과 AI가 같은 원격 컴퓨터를 사용하면서 디버깅·운용·점검·QA·파일 작업을 하나의 앱·CLI·MCP에서 수행하는 환경을 만든다. 기존 Jump Desktop과의 결합을 우선한다.**

이 문서는 다른 에이전트가 구현하기 위한 인계안이다. 이번 작업은 문서 작성이며 신규 제품 구현·설치·배포를 수행하지 않았다. 사용자 요구와 설계 제안, 문서상 기능과 실측 성공을 구분한다.

## 구현자가 먼저 알아야 할 사실

- **Jump Desktop 공식 Jump CLI Beta와 MCP 서버가 존재한다.** 화면 조작과 사람의 관찰·제어권 인계 기능이 문서화돼 있다. 이를 놓친 이전 조사는 불완전했다. [공식 문서](https://docs.jumpdesktop.com/cli/mcp/)
- 이 경로는 현재 머신에서 아직 설치·실행 검증하지 않았다. 구현 0단계에서 가장 먼저 검증할 후보다. 공식 기능으로 충족하는 부분은 재구현하지 않는다.
- 기존 Windows-MCP 실험에서는 앱 실행·한글 입력·저장·파일 재조회·화면 캡처·PowerShell 실행이 성공했다. 그러나 화면 세션 의존 오류와 수동 재시작, SSH 자동 재연결 부재가 있어 완성된 통합 환경으로 판정하지 않았다.
- 사용자는 단순 MCP 도구 모음이 아닌 **운용 가능한 앱과 CLI**를 원한다. UI·CLI·MCP가 같은 대상, 세션, 작업, 파일 전송 상태와 검증 결과를 공유해야 한다.
- 파일 전송/이동은 필수 범위다. Fluid 클립보드만으로 해결한다고 가정하지 않는다.
- Jump 플러그인 SDK/화면 임베딩 API는 확인되지 않았다. 외부 앱·공식 CLI/MCP·연결 링크를 통한 통합을 기본 제안으로 둔다.

## 권장 출발점

`Jump 공식 원격 화면/입력 + 작은 통합 제어 계층 + SSH/원격 에이전트의 명령·파일·진단 + 디버거 어댑터`

이 구성은 **제안**이다. Jump CLI의 실제 도구 계약·버전·라이선스·세션 유지·제어권 인계를 실측한 뒤 구성 요소를 확정한다. 언어/GUI 프레임워크, 프로토콜 전면 자체 개발, 새 클라우드 인프라는 선결정하지 않았다.

## 이번 문서에서 고정한 제품 기준

- 첫 번째 검증 환경은 현재의 macOS 제어기 → Windows 11 x64 실기기다.
- Jump를 사람이 열어둬야만 AI 작업이 가능한 상태는 최종 통과가 아니다.
- 잠금·로그아웃·UAC에서 OS 보호를 우회하지 않는다. 가능한 백그라운드 작업은 계속하고 UI 작업은 정확한 이유와 함께 대기/인계한다.
- 연결이 복구되어도 결과를 모르는 클릭·명령을 자동 재실행하지 않는다.
- 사람은 AI 없이도 연결·터미널·파일·진단·QA를 사용하고, 진행 중 AI를 중지하거나 제어권을 가져올 수 있어야 한다.
- “도구 호출 성공”과 “앱 기능 검증 성공”을 별도 결과로 표시한다.
